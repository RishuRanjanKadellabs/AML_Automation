1. Introduction

1.1 Purpose

This Functional Specification Document (FSD) describes the De-Duplication Screening module of the Clari5 AML platform. It covers the business objective, user interactions, screen components, data inputs/outputs, business rules, and acceptance criteria for the module.



1.2 Scope

Identification of duplicate customer records within the bank's core system

Configurable multi-parameter matching across KYC identity fields

Side-by-side KYC comparison for identified duplicate pairs

Grouped reporting with export capabilities



1.3 Definitions & Abbreviations

Term

Definition

De-Duplication (De-dup)

The process of identifying two or more customer records in a system that represent the same real-world entity.

KYC

Know Your Customer — regulatory process for identity verification of bank customers.

Match Parameter

A KYC data field (e.g. Passport No., Aadhar Card, PAN) used as the basis of comparison for duplicate detection.

Match Score

A percentage indicating the similarity confidence between two customer records for a given matching group.

Group ID

A system-generated identifier (e.g. GRP-0001) assigned to a set of records detected as duplicates.

AML

Anti-Money Laundering — regulatory framework to prevent illegal financial flows.

PAN

Permanent Account Number — a unique 10-character alphanumeric tax identifier issued by the Indian Income Tax Department.



2. Module Overview

2.1 Business Context

Banks maintain large customer databases accumulated over years. The same customer may have been onboarded multiple times under slightly different names, addresses, or using partial identity documents. These duplicate records create compliance risks, inflate AML alert volumes, and complicate regulatory reporting.



The De-Duplication Screening module enables compliance officers and analysts to identify such duplicate records by systematically comparing KYC parameters across the customer base. The module is positioned within the Sanction Screening section of the Clari5 AML platform.

9. Business Rules

9.1 Report Generation

The user must select at least one Match Parameter before generating a report.

If Customer ID is provided, results are filtered to groups containing that customer.

If no Customer ID is provided, the report covers all customers in the system matching the selected parameters for today.



9.2 Duplicate Matching Logic

Two customer records are grouped as duplicates if they share an identical value for at least one selected match parameter.

Multiple parameters can match simultaneously; all matched parameters are displayed in the Match Parameters column.

The Match Score reflects the percentage of selected parameters that match between the two records.

Records with Account Status of "Closed" may still appear in duplicate groups for historical compliance tracking.



9.3 Group Management

Each duplicate group is assigned a unique, sequential Group ID (GRP-XXXX).

A group may contain more than two records if multiple records share the same identity parameter value.

Active Groups are those not yet reviewed or resolved by a compliance officer.



9.4 Data Display Rules

Fields with no available data display as "N/A" or "—" (em dash) in the comparison modal.

ID numbers in the results table are rendered in monospace font for readability.

Matched fields in the comparison modal are visually highlighted in amber.

The "Active Group" status indicator uses a green dot for visual emphasis.

12. Acceptance Criteria

12.1 Filter & Search

User can select one or more match parameters from the multi-select dropdown.

Select All / Deselect All toggles function correctly.

Search within the dropdown filters options correctly in real time.

Parameter tags are displayed and individually removable in the trigger box.

Customer ID field accepts input and filters results correctly when provided.

Clear Filters resets all controls to their default state.



12.2 Report Generation

Clicking Generate Report shows a loading spinner for approximately 1 second.

The Results Section appears and scrolls into view after generation.

The results table displays the correct number of duplicate groups and records.

Group ID, Customer IDs, names, match parameters, and ID numbers render correctly.

The Compare button is available for each group.



12.3 KYC Comparison Modal

Compare button opens the modal with the correct customer names in the header.

Match parameter and match score are displayed accurately in the subtitle.

Both customer records are displayed side by side with all 12 KYC fields.

Matched fields are highlighted in amber in both columns.

Modal closes on ✕ button click, overlay background click, or Escape key.



12.4 Export

All four export options are available from the Export dropdown.

Selecting an export option shows the appropriate toast notification.

Print option opens the browser print dialog.
